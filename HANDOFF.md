## 1. Startup procedure

### The designer, before the session
1. Duplicate the previous build folder in `BUILDS/` and rename it `GIOVANNI_<yymmdd>` (today's date). Never edit an earlier dated folder: each is a backup.
2. Open Claude Code **in the new folder**, so `CLAUDE.md` loads `BUILD-BRIEF.md` and this file automatically.
3. First message: "Start up: follow HANDOFF.md section 1."

### Claude, at the start of every session
1. Read this whole file, then `BUILD-BRIEF.md` (the brief; the designer's later answers in section 3 below override its defaults).
2. Confirm the working folder name matches today's dated folder and that it is the folder Claude Code opened in. If it is not, stop and say so.
3. Node is a private copy (no system Node, no Homebrew): `export PATH="/Users/jzk/Desktop/CLAUDE/GIOVANNI FUSETTI/BUILDS/.tools/node/bin:$PATH"`. Check `node -v` (v24.x).
4. `npm run build` must pass (about 51 pages). If `node_modules` is missing, `npm ci`.
5. Preview server (see section 5): open `/Users/jzk/Desktop/CLAUDE/GIOVANNI FUSETTI/.claude/launch.json` and check its paths point at **this** dated folder (it holds absolute paths and is shared by all folders). Fix it if not, then start the preview.
6. Check the archive is reachable: `../../WORDPRESS/site-archive/` (relative to the build folder). The import scripts in `tools/` expect that layout.
7. Report back in a few lines: folder, build result, preview URL, what was done last, and the next suggested step. Then wait for direction.

### Claude, closing a session (do this when the designer says they are done, or before a handoff)
- Update section 2 (status), section 3 (decisions) and section 6 (open items) of this file, and add a line to the session log in section 8.
- Update the memory note `giovanni-site-project` if conventions changed.
- Make sure `npm run build` passes and `dist/` is fresh (kept locally as a ready-to-open copy; it is not committed to GitHub).

### Working agreements (how the designer likes to work)
- Step by step, one design element at a time, in the order of the designer's checklist. "Table it" means park it, keep the work, do not delete.
- Show options visually before applying: build a review page in `src/design/` (local only, never published) with 3 to 5 alternatives, give a recommendation,
  and flag opportunities for colour and personality that the instructions did not mention.
- Check colour contrast with numbers and say honestly when something fails (white on the logo red fails for small text; red text on the photo cannot be made legible by darkening alone).
- Never change his words. List suspected typos for the designer instead. Mixed-language events get split into the two language fields.
- Ask before anything outward-facing (pushing to GitHub, sending forms, changing DNS, touching the live WordPress site). Do not change domain or DNS.
- Explain in plain language; the designer is not a programmer. Do not claim something looks right without checking it in the preview.
